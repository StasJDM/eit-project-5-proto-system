# Протокол устройства `eit-json-stream/1`

Транспорт: TCP, UTF-8, один JSON-объект на строку. Максимальное время
подключения и чтения задаётся `DataSourceTimingPolicy`.

## Согласование версии

Клиент отправляет:

```json
{"type":"hello","protocol":"eit-json-stream","protocol_version":1}
```

Устройство отвечает:

```json
{"type":"ack","command":"hello","protocol":"eit-json-stream","protocol_version":1}
```

Несовпадение имени или версии блокирует дальнейшую работу.

## Команды

`configure` передаёт ток, частоту, число электродов и поясов, FPS и профиль
`adjacent-16x13-hypothesis-v1`. `start` начинает поток, `stop` безопасно его
останавливает. На `hello`, `configure` и `start` требуется `ack` той же версии.

## Кадр

```json
{
  "type": "frame",
  "protocol_version": 1,
  "sequence_number": 42,
  "timestamp_utc": "2026-10-25T12:00:01.680000Z",
  "belt_index": 0,
  "protocol_id": "adjacent-16x13-hypothesis-v1",
  "channels": [208 чисел],
  "quality": "valid",
  "electrode_quality": [16 чисел 0..1 или null]
}
```

`electrode_quality` содержит фактическую диагностику контакта электродов 1–16.
`null` обозначает техническую ошибку диагностического канала. Для обратной
совместимости поле может отсутствовать, но в этом случае приложение безопасно
блокирует старт исследования до появления диагностики.

Кадр проверяется по контракту TASK-14. Чтение выполняется в отдельном daemon
потоке. Пропуски sequence создают событие `frame_gap`; повреждение, обратный
sequence, отключение или серия таймаутов переводят адаптер в `failed`.

Этот протокол является согласованной границей программного адаптера. Для
прибора с иным штатным протоколом требуется отдельная реализация
`DeviceTransport`; доменный `DataSource` и pipeline не меняются.
