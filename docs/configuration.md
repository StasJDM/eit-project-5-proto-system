# Конфигурация запуска

Приложение читает конфигурацию из переменных окружения при старте.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `EIT_DATA_MODE` | `fromfile` | Источник данных: `simulation`, `fromfile` или `device` |
| `EIT_SIMULATION_SEED` | `0` | Seed воспроизводимого симулятора |
| `EIT_SIMULATION_SCENARIO` | `eupnea` | `eupnea`, `apnea`, `tachypnea`, `electrode_loss`, `noise` или `disconnect` |
| `EIT_SIMULATION_SPEED` | `1.0` | Скорость демонстрационного воспроизведения |
| `EIT_SIMULATION_RR_BPM` | `12.0` | Частота дыхания для обычного сценария, 5–30 дыханий/мин |
| `EIT_SIMULATION_DURATION_SECONDS` | `300.0` | Длительность конечного сценария |
| `EIT_FROMFILE_PATH` | `examples/fromfile/test_3.json` | Файл с 208-канальными кадрами для режима `fromfile` |
| `EIT_FROMFILE_SPEED` | `0.5` | Скорость воспроизведения файла; `0.5` — вдвое медленнее, `2.0` — вдвое быстрее |
| `EIT_DATABASE_PATH` | `data/<mode>/eit.sqlite3` | SQLite-файл метаданных |
| `EIT_RAW_DATA_DIR` | `data/<mode>/frames` | Каталог сжатых NPZ-чанков кадров |
| `EIT_EXPORT_DIR` | `exports` | Каталог экспорта |
| `EIT_BREATH_MODEL_PATH` | соседний `breathclf_identification_0.0.4/models/newborn_mlp_tanh_20261103_112718.joblib` | Путь к модели классификации типа дыхания breathclf 0.0.4 |
| `EIT_DEVICE_ENDPOINT` | не задан | Адрес или идентификатор реального устройства |
| `EIT_LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` |
| `EIT_LOG_PATH` | `data/<mode>/logs/eit.jsonl` | Файл структурированного технического журнала |
| `EIT_LOG_MAX_BYTES` | `2000000` | Максимальный размер одного файла до ротации |
| `EIT_LOG_BACKUP_COUNT` | `5` | Число ротированных файлов |

Неизвестный `EIT_DATA_MODE` безопасно заменяется на `simulation` и создаёт диагностическое сообщение. Некорректные seed и уровень логирования также заменяются безопасными значениями с диагностикой.

Режим `fromfile` читает запись через тот же контракт `DataSource`, реконструкцию
и конвейер мониторинга, что и остальные режимы. По умолчанию используется
одно-кадровый фантом двух кругов
`examples/fromfile/2x_circle_r0.15_20260608_211810.json` из
`eit_project_3_measurements_generator`. Для минимальной трёхкадровой опоры его
единственный кадр детерминированно повторяется без изменения чисел. Поскольку
отдельного baseline в файле нет, time-difference карта относительно этого же
кадра статична. Для динамической демонстрации доступен
`examples/fromfile/eupnea.json` из `eit_project_4_monitoring` с 300 кадрами при
25 Гц. Записи режима `fromfile` маркируются как симулированные и хранятся
отдельно от исследований, полученных от реального устройства.

Полный перечень комплектных файлов, их происхождение и число кадров приведены в
[`examples/fromfile/README.md`](../examples/fromfile/README.md). Все файлы этого
каталога автоматически проверяются строгим 16-электродным/208-канальным
загрузчиком.

Пример запуска:

```bash
EIT_DATA_MODE=fromfile EIT_FROMFILE_PATH=examples/fromfile/eupnea.json python3 main.py
```

Без `EIT_DATA_MODE` приложение запускает статический фантом
`examples/fromfile/2x_circle_r0.15_20260608_211810.json`. Для динамической записи
укажите `EIT_FROMFILE_PATH=examples/fromfile/eupnea.json`, для генеративного
симулятора — `EIT_DATA_MODE=simulation`.

В стартовом режиме `EIT_DATA_MODE=fromfile` запись воспроизводится циклически,
чтобы демонстрационный мониторинг не останавливался на последнем кадре. Между
циклами сохраняются строго возрастающие номера и временные метки кадров.
Архивное воспроизведение завершённого исследования и импорт через экран пациента
остаются конечными и останавливаются в конце записи.

Для отображения в естественном реальном времени используйте
`EIT_SIMULATION_SPEED=1`. Значения больше `1` намеренно ускоряют поступление
кадров и визуальное движение дыхательной кривой. Частота дыхания обычного
сценария задаётся отдельно через `EIT_SIMULATION_RR_BPM`.

## Классификация типа дыхания

Вкладка «Тип патологического дыхания» использует модель формата
`breathclf_identification 0.0.4`. По умолчанию приложение ищет модель
`newborn_mlp_tanh_20261103_112718.joblib` в соседнем каталоге
`breathclf_identification_0.0.4/models`; для поставки модели в другом месте
задайте `EIT_BREATH_MODEL_PATH`.

Модель обучена для новорождённых и требует непрерывную глобальную кривую за
60 секунд. Приложение детерминированно пересчитывает фактические 25 Гц в 10 Гц,
требуемые моделью, и показывает класс, уверенность, версию модели, PCA обучающей
выборки и встроенные усреднённые шаблоны. Интеграция помечена как
экспериментальная: метрики из bundle отражают внутреннюю кросс-валидацию модели
и не заменяют независимую клиническую валидацию.

По умолчанию режимы используют разные базы и каталоги кадров. Дополнительно БД хранит свой режим в `database_metadata` и отклоняет открытие из другого режима. Репозитории не разрешают записать реальные исследования в демонстрационную БД и наоборот.

`device` выбирает аппаратный источник `eit-json-stream/1` и показывает активный режим в существующей строке «Модель устройства» экрана системной информации. Endpoint задаётся как `tcp://host:port`; формат handshake, команд и кадров описан в [протоколе устройства](device_json_stream_protocol.md). При отсутствующем endpoint приложение запускается без потока кадров и выводит диагностическое сообщение вместо аварийного завершения.

Во время исследования входящие кадры автоматически пишутся в
`<EIT_RAW_DATA_DIR>/recordings` согласно [формату записи](raw_recording_format.md).

## Технические журналы

Каждая строка журнала является отдельным JSON-объектом с UTC-временем, уровнем, техническим кодом события и при наличии — `correlation_id`, `study_id`, `session_id`. Свободный текст и произвольные поля в технический журнал не записываются. Разрешён только ограниченный набор диагностических полей без ФИО, медицинских значений и иных персональных данных.
