# Формат записи входных кадров исследования

Каждое исследование записывается в каталог
`<raw_data_dir>/recordings/<study UUID>/<session UUID>/`.

## Manifest

`manifest.json` версии 1 хранит UUID исследования и сессии, режим
simulation/fromfile/device, частоту кадров, тип кадра, протокол и число каналов,
статус `recording|completed|interrupted`, число подтверждённых кадров и список
чанков. Для каждого чанка записаны первый/последний sequence, количество
кадров и SHA-256.

Manifest заменяется атомарно через временный файл и `os.replace`. Он
обновляется только после полного `fsync` и атомарной установки NPZ-чанка.

## Чанки

Кадры накапливаются в памяти и записываются пакетами по 64. Общие массивы:

- `sequence_number`, `timestamp_utc`, `belt_index`;
- `quality`, `simulated`.

Для аппаратного `RawMeasurementFrame` сохраняются 208 `channel_values`,
`protocol_id` и `timestamp_source`. Для симуляционного `EITFrame` сохраняются
входящие global/ROI/map значения без изменения числовой точности (`float64`).

Перед записью проверяются режим, возрастающий sequence и свободное место с
резервом 64 MiB. При чтении проверяются SHA-256, количество кадров и порядок.

## Восстановление

При старте `recover_incomplete()` находит manifest со статусом `recording`,
повторно индексирует только полностью установленные непустые NPZ-файлы,
пересчитывает SHA-256 и отмечает запись `interrupted`. Скрытые временные файлы
не считаются подтверждёнными. Поэтому аварийное завершение может потерять
только ещё не сброшенный RAM-буфер или незавершённый временный файл, но не
повреждает уже подтверждённые чанки.
